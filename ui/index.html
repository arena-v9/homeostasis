Learning curves

Greedy policy on 64 fixed layouts, evaluated during training. Dashed line: random policy.

Diagnostics

Catastrophic-forgetting checks from ARENA's DQN chapter, at each evaluation (see runs/diagnostics.py): the share of the replay buffer that is deaths, the TD loss on a large buffer sample, the gap between the best and worst action's Q-value, and how far the Q-values of doomed states (every action dies next step) are from their true value.

Survival is the fraction of test episodes in which the agent stays alive for all 100 steps. Every 8k environment steps, each run is tested on the same 64 fixed layouts.

    Methods

    • Evaluations: every 8k environment steps, the greedy policy plays one episode on each of the same 64 fixed layouts.
    • Reliability: the share of a run's evaluations after 100k environment steps (13 of them) with at least 95% survival. Deaths by cause are counted over the same evaluations (13 × 64 = 832 episodes per run) and given per 1,000 episodes.
    • Comparisons: the answers compare each group with the one listed before it, which differs from it in one setting. The table in section 1 also compares each group with every group before it.
    • 95% interval: bootstrap over training runs (20,000 resamples). A difference is called clear only when its interval excludes zero and p < 0.05. A clear survival difference under 0.02 is called negligible.
    • p-value: two-sided permutation test, shuffling runs between the two groups. For the same networks tested in both settings (section 2), a sign-flip test on each run's difference.
    • Final-network tests (section 2): each run's saved network at the end of training, greedy, one episode on each of 512 fixed layouts. One snapshot per run.
    • Cause of death: "fire" if the agent died standing on fire, "starvation" otherwise (the only other way to lose health).
